# DocEval AI

DocEval AI is a benchmarking tool and dataset designed to evaluate how well Large Language Models generate technical documentation (specifically README files).

When evaluating an LLM's ability to document a codebase, we look at five specific criteria: Accuracy, Completeness, Hallucination Prevention, Structure & Clarity, and Appropriate Scope. This repository provides both a manually annotated dataset of 28 real open-source repositories and a web application to explore the data and run your own evaluations.

## What's included

**The Benchmark Dataset**  
I've included a dataset of 28 human-audited README outputs. These were generated by various LLM APIs (like Groq's Llama 3.3 70B and Gemini) for real public GitHub repositories, ranging from small utilities like `lukeed/clsx` to massive frameworks like `facebook/react`. I manually audited each output against the source code to provide accurate scores and qualitative notes.

**Automated QA Audit Tool**  
The project also includes a web interface that can fetch a repository's file tree and package dependencies, pass them to an LLM, and attempt to score the generated README against the 5-metric rubric. It uses a rotation of providers (Groq, OpenRouter, Gemini) to handle rate limits automatically.

**Analysis and Export**  
You can search the dataset, filter by complexity or failure modes (score <= 2), view statistical charts, and export the entire dataset to JSON or CSV for your own use.

## How we evaluate (The Rubric)

Each README is scored from 1 to 5 based on the following:
- **Accuracy**: Does the documentation accurately reflect the actual source code, languages, and dependencies?
- **Completeness**: Are all the essential sections there? (Installation, Usage, API details, Contributing, License)
- **Hallucination**: Did the model invent fake CLI flags, invalid install commands (like `npm install deno`), or mention deprecated APIs?
- **Structure & Clarity**: Is the markdown properly formatted with a readable heading hierarchy?
- **Appropriate Scope**: Is the level of detail appropriate for the size of the codebase?

## Running the project locally

You'll need Node.js (v18+) and npm installed.

1. Clone the repository and install dependencies:
   ```bash
   git clone https://github.com/KalashMaheshwari/DocEval-AI.git
   cd DocEval-AI
   npm install
   ```

2. Set up your environment variables by copying the example file:
   ```bash
   cp .env.example .env
   ```
   Then add your API keys for Groq, OpenRouter, or Gemini.

3. Start the development server:
   ```bash
   npm run dev
   ```
   The app will be running at `http://localhost:3000`.

## Architecture overview

- `dataset.json`: The core JSON database storing the 28 manually annotated evaluations.
- `server.ts`: An Express backend that handles GitHub tree parsing and LLM API requests.
- `src/`: The React frontend, including the dataset viewer, interactive rubric, and live evaluation tool.
